# d_rocket 2.4.0 Integrations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the seven integration improvements described by the 2.4.0 design while keeping the core Dart package independent from Flutter.

**Architecture:** Extend the existing runtime clients additively. Keep codegen discovery in `d_rocket_builder`, diagnostics/retry/transport/SSE behavior in `d_rocket`, and place Flutter controller bindings in a separate `d_rocket_flutter` package. Preserve the existing per-class serializer and retry APIs as compatibility paths.

**Tech Stack:** Dart `^3.11.5`, Flutter adapter package, `package:http`, `build_runner`, analyzer/source_gen, existing d_rocket form/serializer/REST/realtime APIs.

**Spec:** `docs/superpowers/specs/2026-11-21-d-rocket-2.4.0-integrations-design.md`

## Global Constraints

- Release line is `2.4.0`.
- Core Dart packages must not depend on Flutter.
- Existing public APIs remain source-compatible where an additive API is possible.
- Generated files are produced by build_runner and are never hand-edited.
- Production code follows one class, enum, or explicit language feature per file.
- Every behavior change starts with a failing regression test.
- `d_rocket_engine_sqlite` changes only if a failing integration test proves they are required.

## Review Focus

- Concrete nested generic types must be discovered without registering unconstrained type parameters; test `ResponseModel<List<VehicleResponse>>` and nullable data.
- A transport policy must see the final URI and must not leak credentials across an origin-changing redirect; test REST, SSE, and download paths separately.
- Retry defaults must not repeat ambiguous mutations, while cancellation must interrupt backoff; test both a GET and a POST timeout.
- Diagnostic redaction must cover mixed-case headers and nested map/list body values; assert sensitive values never appear in serialized diagnostics.
- SSE ownership must be correct for pending, active, repeated-close, owned, and shared transports; assert the shared transport remains usable.
