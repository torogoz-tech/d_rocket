# d_rocket 2.1.0 — minimum production flow

This example shows the recommended order for an offline-first Flutter
application: model and code generation, SQLite, synchronization, mobile
connectivity and DevTools diagnostics.

## Dependencies

```yaml
dependencies:
  d_rocket: ^2.1.0
  d_rocket_engine_sqlite: ^2.1.0
  d_rocket_engine_mobile: ^2.1.0

dev_dependencies:
  d_rocket_builder: ^2.1.0
  d_rocket_lints: ^2.1.0
  build_runner: ^2.4.13
```

## Entity and code generation

```dart
import 'package:d_rocket/d_rocket.dart';

part 'evento.d_rocket_orm.g.dart';
part 'evento.d_rocket_serializer.g.dart';

@Table(name: 'eventos')
@Serializable()
class Evento {
  Evento({
    required this.id,
    required this.nombre,
    required this.activo,
    required this.monto,
    required this.timestamp,
    this.descripcion,
  });

  @PrimaryKey(autoIncrement: false)
  final String id;

  @Column()
  final String nombre;

  @Column()
  final String activo;

  // double/num are the supported decimal-equivalent types.
  @Column()
  final double monto;

  @Column()
  final DateTime timestamp;

  @Column(nullable: true)
  final String? descripcion;
}
```

Then run:

```bash
dart run build_runner build --delete-conflicting-outputs
```

An exact `Decimal`/`BigDecimal` value should not be passed directly to the
code generator. For JSON, declare a `@JsonKey(converter: 'money')`; for
SQLite, use `String` or a scaled `int`, with an explicit conversion in the
domain layer.

## SQLite initialization

```dart
void initializeDataLayer() {
  dRocketSqlite();
  initializeD();
}

final db = await Db.open(path: 'app.db');
final eventos = db.set<Evento>();
```

LINQ queries intended for persistence must use expressions translatable to
SQLite. The provider rejects unsupported expressions with an explicit error;
it never silently executes a different in-memory query.

## Synchronization

```dart
final connectivity = ConnectivityPlusProvider();
final sync = RestSyncProvider(
  baseUrl: 'https://api.example.com',
  headers: <String, String>{'Authorization': 'Bearer $token'},
);

context.connectivity = connectivity;
final trigger = PeriodicSyncTrigger(
  interval: const Duration(minutes: 5),
);
trigger.start(() => context.syncAsync(sync, clientId: deviceId));
```

A retry must reuse the same `SyncChange.changeId`. The server must store
those keys per client and discard duplicates. The local watermark advances
only after a successful response.

Use `WebSocketSyncProvider` for realtime changes and `RestSyncProvider` as a
fallback transport or initial synchronization channel.

## DevTools

In debug mode, register the bridge once:

```dart
void main() {
  DrocketDevToolsBridge.register();
  initializeDataLayer();
  runApp(const App());
}
```

The `d_rocket` extension displays real REST, SQLite, migration, sync,
WebSocket and SSE events. Each row is sorted by timestamp and opens a modal
with the request/response, SQL, duration, status and error. Tokens, cookies
and sensitive values remain redacted by default.

## Migrations

```bash
dart run d_rocket:migration check \
  --db app.db \
  --entities lib/data/db/entities.dart

dart run d_rocket_engine_sqlite:migration run \
  --db app.db \
  --migrations lib/data/db/migrations.dart
```

Destructive operations require manual review. The CLI reports them, prints
the proposed SQL and returns a non-success exit code until the review is
confirmed.

## Local validation

```bash
dart analyze

dart run build_runner build --delete-conflicting-outputs
flutter analyze

```
