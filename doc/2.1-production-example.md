# d_rocket 2.1.0 — flujo mínimo de producción

Este ejemplo muestra el orden recomendado para una aplicación Flutter
offline-first: modelo y codegen, SQLite, sincronización, conectividad móvil y
diagnósticos visibles en DevTools.

## Dependencias

```yaml
dependencies:
  d_rocket: ^2.1.0
  d_rocket_engine_sqlite: ^2.1.0
  d_rocket_engine_mobile: ^2.1.0

dev_dependencies:
  d_rocket_builder: ^2.1.0
  d_rocket_lints: ^2.1.0
  build_runner: ^2.4.13
```

## Entidad y codegen

```dart
import 'package:d_rocket/d_rocket.dart';

part 'evento.d_rocket_orm.g.dart';
part 'evento.d_rocket_serializer.g.dart';

@Table(name: 'eventos')
@Serializable()
class Evento {
  Evento({
    required this.id,
    required this.nombre,
    required this.activo,
    required this.monto,
    required this.timestamp,
    this.descripcion,
  });

  @PrimaryKey(autoIncrement: false)
  final String id;

  @Column()
  final String nombre;

  @Column()
  final String activo;

  // double/num are the supported decimal-equivalent types.
  @Column()
  final double monto;

  @Column()
  final DateTime timestamp;

  @Column(nullable: true)
  final String? descripcion;
}
```

Después se ejecuta:

```bash
dart run build_runner build --delete-conflicting-outputs
```

Un objeto `Decimal`/`BigDecimal` exacto no debe llegar directamente al
codegen. Para JSON se debe declarar un `@JsonKey(converter: 'money')`; para
SQLite se recomienda `String` o un `int` escalado, con conversión explícita en
la capa de dominio.

## Inicialización SQLite

```dart
void initializeDataLayer() {
  dRocketSqlite();
  initializeD();
}

final db = await Db.open(path: 'app.db');
final eventos = db.set<Evento>();
```

Las consultas LINQ destinadas a persistencia deben utilizar expresiones
traducibles a SQLite. El proveedor rechaza expresiones no soportadas con un
error explícito; no ejecuta silenciosamente una consulta distinta en memoria.

## Sincronización

```dart
final connectivity = ConnectivityPlusProvider();
final sync = RestSyncProvider(
  baseUrl: 'https://api.example.com',
  headers: <String, String>{'Authorization': 'Bearer $token'},
);

context.connectivity = connectivity;
final trigger = PeriodicSyncTrigger(
  interval: const Duration(minutes: 5),
);
trigger.start(() => context.syncAsync(sync, clientId: deviceId));
```

Un reintento debe reutilizar el mismo `SyncChange.changeId`. El servidor debe
guardar esas claves por cliente y descartar duplicados. El watermark local solo
avanza después de una respuesta exitosa.

Para WebSocket se usa `WebSocketSyncProvider` para cambios en tiempo real y
`RestSyncProvider` como transporte de respaldo o sincronización inicial.

## DevTools

En modo debug se registra el bridge una sola vez:

```dart
void main() {
  DrocketDevToolsBridge.register();
  initializeDataLayer();
  runApp(const App());
}
```

La extensión `d_rocket` muestra eventos reales de REST, SQLite, migraciones,
sync, WebSocket y SSE. Cada fila se ordena por timestamp y abre un modal con
request/response, SQL, duración, estado y error. Tokens, cookies y valores
sensibles permanecen redactados por defecto.

## Migraciones

```bash
dart run d_rocket:migration check \
  --db app.db \
  --entities lib/data/db/entities.dart

dart run d_rocket_engine_sqlite:migration run \
  --db app.db \
  --migrations lib/data/db/migrations.dart
```

Las operaciones destructivas requieren revisión manual. El CLI las reporta,
muestra el SQL propuesto y devuelve un código de salida no exitoso cuando la
revisión no ha sido confirmada.

## Validación local

```bash
dart analyze
dart test
dart run build_runner build --delete-conflicting-outputs
flutter analyze
flutter test
```

El ejemplo SQLite ejecutable está en `d_rocket_engine_sqlite/example/` y el
