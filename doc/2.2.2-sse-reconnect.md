# Robust SSE in d_rocket 2.2.4

`SseReconnector` maintains a Server-Sent Events connection and exposes a
controlled lifecycle for offline-first applications. This release does not
change build or code generation; the change is limited to realtime transport.

## Dynamic headers

`headersProvider` runs before every connection, including every reconnect.
This lets the client obtain the current token instead of reusing stale
headers:

```dart
final SseReconnector stream = SseReconnector(
  factory: HttpSseClient.new,
  url: Uri.parse('https://api.example.com/events'),
  headersProvider: () async => <String, String>{
    'Authorization': 'Bearer ${await session.accessToken()}',
  },
);
```

When the server returns `401`, `onUnauthorized` can refresh the session. If
it returns `true`, the next connection resolves `headersProvider` again. If
it returns `false`, the lifecycle ends in `failed`. A `403` is reported as
`SseHttpException` and does not start indefinite retries.

## States and shutdown

The available states are `connecting`, `connected`, `retrying`, `stopped` and
`failed`:

```dart
final states = stream.states.listen((state) {
  print(state);
});

await stream.start();
await stream.stop(); // also cancels retries and the active transport
await stream.start(); // starts a new generation
await stream.dispose(); // also closes events and states
await states.cancel();
```

Callbacks from an earlier connection are ignored after `stop()` or a new
`start()`, so a late event cannot contaminate the current generation.

## Cursor and manual processing

By default, the cursor advances when an event with an `id` is received. To
advance it only after saving or processing the payload, enable
`manualAcknowledge`:

```dart
final stream = SseReconnector(
  factory: HttpSseClient.new,
  url: Uri.parse('https://api.example.com/events'),
  manualAcknowledge: true,
);

stream.events.listen((event) async {
  await repository.save(event.data);
  stream.acknowledge(event);
});

stream.clearLastEventId();
```

The cursor is sent in `Last-Event-ID` during the next connection.

## Inactivity and heartbeats

`inactivityTimeout` resets on any transport activity, including SSE comments
(`: heartbeat`) that do not contain business changes. When it expires, the
connection closes and enters the same controlled reconnect flow.

```dart
final stream = SseReconnector(
  factory: HttpSseClient.new,
  url: Uri.parse('https://api.example.com/events'),
  inactivityTimeout: const Duration(minutes: 2),
);
```

## Direct `HttpSseClient` configuration

Since 2.2.4, the SSE transport can be configured directly without creating a
subclass or an `http.Client` adapter in the application:

```dart
final client = HttpSseClient(
  defaultHeaders: <String, String>{
    'Cache-Control': 'no-cache',
  },
  connectTimeout: const Duration(seconds: 10),
  followRedirects: false,
  interceptors: <SseInterceptor>[
    AddTenantHeaderInterceptor(),
  ],
);
```

`connectTimeout` limits only the initial HTTP response wait; it does not
limit the lifetime of the SSE stream. Stream inactivity is controlled with
`SseReconnector.inactivityTimeout`.

Interceptors receive the request, initial response and lifecycle errors:

```dart
class AddTenantHeaderInterceptor extends SseInterceptor {
  @override
  Future<http.BaseRequest> onRequest(http.BaseRequest request) async {
    request.headers['X-Tenant-Id'] = 'tenant-42';
    return request;
  }
}
```

`401`, `403` and other HTTP statuses are preserved so `SseReconnector` can
apply its authentication and retry rules. A successful response must declare
`Content-Type: text/event-stream`, unless `validateContentType: false` is
configured.

Normal usage does not require injecting a transport:

```dart
final client = HttpSseClient();
```

Optional `http.Client` injection remains available for tests or specialized
transports. When `HttpSseClient` creates the transport, `close()` also
releases it; an injected transport remains owned by the caller.

`HttpSseClient` closes the response subscription in `close()`. When it created
the HTTP client internally, it also releases that client; when it receives an
injected client, it does not close it because ownership remains with the
caller.

## Other 2.2.2 improvements

The same framework and builder release also fixes escaping for `@Pattern`
expressions, supports nullable nested models in the serializer and allows an
instance-specific `baseUrl` through `RestClientConfig`.

Generated forms accept cross-field validators:

```dart
final form = PaymentRequestForm(
  validators: <FormValidator<PaymentRequest>>[
    (PaymentRequest? value) => value?.validateCard(),
  ],
);
```

They also expose `bindComposite()` for controls that produce multiple values:

```dart
form.bindComposite<String>((String value) => <String, Object?>{
  'expirationMonth': value.substring(0, 2),
  'expirationYear': value.substring(3),
});
```
